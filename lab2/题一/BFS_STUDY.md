# 补充探究：普通队列是否比更少节点的 A* 更快？

## 研究问题

题一每条边的代价均为 1，普通 BFS 同样保证最短路径。此前 BFS 只用于验证答案，`h=0` 仍使用堆，无法直接回答“引导搜索的收益能否抵消数据结构成本”。本组加入普通BFS，并在同一个内核中仅切换队列与堆，区分引导搜索的收益和数据结构成本。

## 实验设计

比较五种完整调用：

| 方法 | 作用 |
|---|---|
| deque BFS | 普通队列基线，返回完整坐标路径 |
| 匹配内核 / heap | 与 BFS 共用发现、校验、父指针及统计代码，只更换 frontier 适配器 |
| 原 A* / h=0 | 保留已有通用 A* 实现，研究实际实现成本 |
| 曼哈顿 / FIFO | 仅加入几何启发，仍按发现顺序处理同 `f` |
| 曼哈顿 / low_h | 同 `f` 优先较小 `h`，观察有效搜索量减少的收益 |

使用原场景生成器的 14 张地图，再生成边长 `30/60/100`、障碍概率 `0.15/0.30` 的地图，每组 20 个固定种子，共 134 张地图、670 个配置。随机地图不按有解性筛选；新增 120 张图中本次有解 84 张、无解 36 张。每张图的五种方法使用完全相同的地图、端点和右下左上邻居顺序，并打乱配置计时顺序。

每配置预热 1 次，再测 5 批、每批 5 次；报告批平均单次耗时的中位数与最小值。计时包含输入校验、搜索统计、完整路径回溯和少量分派开销，关闭追踪；独立答案核验、地图生成、绘图和文件读写不计时。地图是统计样本，重复计时不是新地图样本。队列峰值是记录数，不是总内存字节。

## 受控不变量

670 个配置的最短步数及路径合法性全部通过独立 BFS 核对。在全部 134 张地图上，普通 BFS、匹配堆内核与原 `h=0/FIFO` 的返回路径和搜索统计完全一致；额外单元测试核对了 200 张随机图及样例的 24 种邻居排列，匹配 deque/heap 的完整有效出队顺序也一致。

因此，匹配内核对照是在搜索工作量相同时研究本次 frontier 适配方案的成本。原 A* 还维护更通用的状态和优先级逻辑，不能把它与 BFS 的全部时间差都归因于堆。

## 结果与机制

下表每格为“扩展节点数 / 毫秒”，扩展数不含目标；时间只代表本组测量环境。

| 场景 | 普通 BFS | 匹配堆 | 原 h=0 | 曼哈顿/FIFO | 曼哈顿/low_h |
|---|---|---|---|---|---|
| 开阔 40×40 | 1599 / 2.4666 | 1599 / 2.8936 | 1599 / 3.9393 | 1599 / 4.1665 | 78 / 0.3275 |
| 强制绕路 | 588 / 1.0651 | 588 / 1.0058 | 588 / 1.3562 | 527 / 1.3660 | 318 / 0.9065 |
| 固定无解图 | 105 / 0.1627 | 105 / 0.2223 | 105 / 0.2749 | 105 / 0.2666 | 105 / 0.2537 |

开阔图中 FIFO 曼哈顿同样扩展 1599 个节点，却增加优先级计算和通用堆处理；`low_h` 将扩展降至 78，收益足以超过这些开销。绕路图中基础曼哈顿从 588 降至 527 个节点，但时间反而更高；节点数和耗时需要同时评价。匹配堆在这一张图中略快于 deque，说明有限批次与机器波动下不应宣称普通队列每次都更快。

对新增随机图逐图计算“方法时间 / 同图 BFS 时间”，再汇总，而不是将两列中位数相除：

| 随机地图分层 | 方法 | 配对时间比中位数 `[Q1,Q3]` |
|---|---|---|
| 有解，84 图 | 匹配堆 | 1.179 `[1.139,1.212]` |
| 有解，84 图 | 原 h=0 | 1.555 `[1.504,1.645]` |
| 有解，84 图 | 曼哈顿/FIFO | 1.212 `[0.734,1.368]` |
| 有解，84 图 | 曼哈顿/low_h | 0.296 `[0.231,0.399]` |
| 无解，36 图 | 匹配堆 | 1.113 `[0.995,1.219]` |
| 无解，36 图 | 曼哈顿/low_h | 1.121 `[1.026,1.850]` |

比值小于 1 表示该方法在该图上耗时更低。四分位数描述地图间差异，不是置信区间。有解图的 FIFO 曼哈顿时间比横跨 1，说明其效果随地图变化；`low_h` 在本批有解图中更有效。无解时，各方法都须耗尽起点连通区域，节点比全部为 1，目标引导不能减少最终必查区域；额外的计算可能只留下成本。

在相同障碍概率 0.15 下，`low_h/BFS` 的有解时间比中位数在边长 30、60、100 时分别为 0.328、0.282、0.236。此现象支持本组较大地图中引导收益更明显，但三种尺寸不是复杂度定律；角落端点、固定并列策略和地图分布共同限定了结论。

## 复杂度、复现与边界

本实现每次完整输入校验需 `O(RC)`。BFS 搜索为 `O(V+E)`，总时间上界 `O(RC+V+E)`，辅助空间 `O(V)`；本题四方向网格有 `E=O(V)`。匹配堆采用二叉堆，增加对数级 frontier 操作。实际常数、Python 字典与函数调用仍会影响时间。

本组没有测量内存字节，也没有证明某方法在所有迷宫上最快。额外的“匹配堆”只用于控制实验，正式题目接口仍为已有 A*。如果边代价不同，首次发现即确定最短距离的普通 BFS 规则不再适用。

运行 `python run_bfs_study.py`，默认参数为 `--seeds 20 --repeats 5 --batch 5 --seed 20261028`。`results/bonus_bfs/` 保存逐配置 CSV、分层汇总、每批计时、完整地图/环境/源码哈希，以及 `time_ratio.svg`、`node_ratio.svg`。同一次测量的文件可共同复现和核对，不能与旧实验不同测量批次的毫秒数混成速度对照。

方法参考：[Red Blob Games 的队列与搜索实现讨论](https://www.redblobgames.com/pathfinding/a-star/implementation.html#queue)。本组比较针对题一自行实现，所有结论来自保存的实际结果。
