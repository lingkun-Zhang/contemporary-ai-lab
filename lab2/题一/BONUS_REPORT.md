# 题一补充实验 搜索成本与正确性边界

## 1. 研究问题与对照

启发函数减少了扩展量之后，程序是否更快，还取决于容器操作、重复状态维护和预处理成本。本章围绕这些成本设置四组实验。

| 研究问题 | 对照方式 | 重点观察 |
|---|---|---|
| 少搜节点是否一定更快？ | 普通队列BFS、同内核匹配堆、原A*的h=0及两种曼哈顿设置 | 节点节省能否抵消单次操作成本 |
| 可采纳启发何时需要重开？ | 2×9反例、走廊变体和未筛选随机图，比较允许重开与冻结闭集 | 更小g能否传播，以及冻结规则何时返回非最优路径 |
| 何时值得预检无解查询？ | 三种地图、不同失败比例，计入建表与查询验证 | 查询规模和失败区域大小怎样影响摊销 |
| 地图间差异是否改变结论？ | 逐图配对、合并重复地图、探索性bootstrap区间 | 收益分布及小样本的不确定性 |

正式接口为 `maze_astar.astar`，返回四方向单位代价的最短坐标路径，无解时返回 `[]`。冻结闭集只作为错误消融，用来检验正确性条件。

## 2. 普通队列基线：分清搜索量与单位操作成本

完整章节见 [BFS_STUDY.md](BFS_STUDY.md)。本组共有 134 个地图输入、5 个设置，670 个搜索配置。除复用基础地图构造外，新增 30/60/100 三种尺寸、两种障碍概率、每组 20 个固定种子的 120 张地图；各算法在同一输入上配对比较。

两种均匀搜索共用验证、发现状态、父指针、终止和统计代码，只切换 `deque` 与堆；它们在全部输入上的路径与搜索工作量一致。因此这对受控版本可讨论容器成本。原 A* 还有不同的数据维护和函数调用开销，不能把它相对 BFS 的所有耗时差都归因于堆。

| 同轮代表场景 | 普通 BFS：扩展/毫秒 | 曼哈顿 FIFO：扩展/毫秒 | 曼哈顿 low_h：扩展/毫秒 |
|---|---|---|---|
| 开阔 40×40 | 1599 / 2.467 | 1599 / 4.167 | 78 / 0.328 |
| 强制绕路 | 588 / 1.065 | 527 / 1.366 | 318 / 0.907 |

强制绕路中，曼哈顿 FIFO 的扩展量下降约 10.37%，但同轮耗时反而更长；low_h 减少的工作量更多，才在该次测量中抵消了额外开销。不能只凭扩展数判断实际运行速度。

120 张新增随机图中，84 张有解、36 张无解。有解组先逐图计算“方法时间/BFS 时间”，其中位数为匹配堆 1.179、原 `h=0` 1.555、曼哈顿 FIFO 1.212、曼哈顿 low_h 0.296。无解时，四种方法与 BFS 的节点比均为 1，low_h 的时间比中位数为 1.121。它们是指定实现、输入与测量轮次的配对结果，不是普遍的算法速度排名。

## 3. 重开消融：把正确性边界变成可观察过程

完整章节见 [REOPEN_STUDY.md](REOPEN_STUDY.md)。使用同一实验内核，仅改变“已扩展节点是否允许通过更小的 g 重新扩展”。禁用重开的版本是故意错误的对照，不用于提交题目答案。

经典反例仍符合题一规则：

```text
S.......E
.....XXXX
```

第 0 行前四格使用 `h=8-col`，其余格使用 0。这是把曼哈顿值逐点降低，所以仍是可采纳下界；但从 `(0,3)` 到 `(0,4)` 有 `5>1+0`，不满足一致性。

| 同图、同启发、同邻居顺序 | 返回步数 | 是否最优 | 机制证据 |
|---|---:|---|---|
| 允许重开 | 8 | 是 | 3 次节点重开，2 次有效出队 `f` 下降 |
| 冻结已扩展节点 | 10 | 否 | 忽略闭集改进，保留较差路径 |

因此，`f` 下降不等于启发函数高估，启发可采纳也不等于启发一致。正确处理更小 g 的传播，才是这里最优性的必要实现条件之一。

实验保留 1 个经典输入、36 个走廊参数变体、120 张随机地图，配合 3 类启发与 2 种策略，共 942 配置。正确版本全部达到独立 BFS 的最短距离，并与原正式 A* 做 471 次交叉核对。错误对照在 36 个走廊变体中有 24 个失去最优；在随机降低曼哈顿值的 81 张有解图中有 7 个失败，另外 39 张无解图也完整保留。一致的零启发与曼哈顿对照均未失败。

“不一致”不是“每次必定出错”；这里展示的是冻结闭集失去最优保证，并用分层失败比例说明现象的适用范围。逐步轨迹和 h 表为机制证据，不只罗列最终输出。

## 4. 连通预检：优化必须算总成本

完整章节见 [CONNECTIVITY_STUDY.md](CONNECTIVITY_STUDY.md)。对静态地图先做四方向连通分量标号。若起终点标签不同，直接返回无解；同分量仍调用正式 A*。

索引保存不可变的地图快照，原矩阵改变后需要重新构建。所有查询分支都保留一次完整地图验证，故完整查询仍包含 O(RC) 扫描，只有标签比较本身是 O(1)。建表包含验证、复制、标号与距离无关的遍历，存储量按标签条目报告。

默认使用三种 80×80 地图、共 11 个负载，每个负载 100 对起终点。两种不连通结构分别控制 0/25/50/75/100% 的无解比例，全连通图只测 0%，共有 1100 对查询、2200 个配置。比例是实验控制的任务构成，不冒充自然分布下的失败概率。

| 100 次查询的场景 | 原 A* 累计 ms | 预检＋A*，含建表 ms | 结果解释 |
|---|---:|---:|---|
| 两大区，100% 无解 | 1326.049 | 66.421 | 避免穷尽大连通区；扩展从 315840 降至 0 |
| 小隔间，100% 无解 | 60.203 | 62.324 | 虽从 900 次扩展降至 0，100 次内仍未回本 |
| 全连通，0% 无解 | 67.486 | 74.074 | 无查询可被拒绝，建表增加总开销 |

累计时间是一次预处理实测值加逐查询重复计时中位数之和，是测量分量的累计估计，不是把整段 100 次连续执行后的一次墙钟时间。单次总成本与首次观测交点也保留在数据中；交点受当前负载及计时噪声影响，不能当作通用阈值。

最重要的结论是：无解比例相同，优化仍可能因起点连通区域大小而得到相反的成本结果。优化要同时看建表、查询、存储与地图是否静态。

## 5. 统计证据：从单个数值到适用范围

完整章节见 [EVIDENCE_AUDIT.md](EVIDENCE_AUDIT.md)。对原规模实验做按地图配对的重采样，审计 75 个非空分组，其中 48 个有至少 5 张不同地图而输出探索性区间。没有把同一地图的计时重复当作独立样本；p=0 的重复空地图合并后，每种尺寸只有 1 个不同输入。

40×40、p=0.2 的 19 张有解图中，曼哈顿 low_h 的逐图节点减少率中位数是 89.11%，探索性 95% 百分位 bootstrap 区间为 87.43%—89.83%。p=0.3 只有 9 张有解图，相应区间为 43.65%—77.54%，证据明显更分散。p=0.4 只有 1 张有解图，不输出区间。

百分位区间没有采用 BCa 修正和多重比较校正，也不包含跨机器性能变化；这里用来限制结论的强度。IQR 描述地图收益的离散程度，bootstrap 区间描述本组统计量的重采样变化，二者不能混用。

## 6. 正式结果、故意错误对照与复现

本组增加 3812 个搜索配置：BFS 对照 670、重开消融 942、连通预检 2200。其中重开实验有 471 个故意冻结闭集的错误对照，错误结果是需要解释的实验现象；其他正确求解配置均通过独立最短距离与路径核验。75 个统计分组来自原数据再分析，不另算作新增地图或搜索配置。

原有 42 个基础配置和 1956 个拓展配置的数据保持原样。各研究分别保存源码哈希、完整输入、随机参数、原始记录和图表；同一研究内配对比较，避免把不同运行轮次的毫秒数混在一起排名。该阶段共40项测试：基础22项、BFS 6项、重开4项、连通索引5项和统计审计3项。地标调参与确认又各增加5项，当前共50项；完整运行入口见 [README.md](README.md)。

当前 Windows 电脑：

```powershell
.\run_q1.cmd tests
.\run_q1.cmd bonus
```

其他已配置 Python 的环境：

```powershell
python -m unittest discover -v
python run_bonus_experiments.py
python run_bonus_experiments.py --study audit
```

总入口的 `--study` 可选 `all/bfs/reopen/connectivity/audit`。自定义规模和计时参数请直接运行各子脚本的 `--help`；Windows 快捷入口不转发研究模式后的额外参数。

BFS受控对照区分了搜索量和容器成本；重开反例说明了可采纳与一致性的差别；连通预检则显示失败查询省下的搜索需要先抵消建表成本。三个实验分别改变不同因素，其完整扫描数据保存在对应结果目录。
